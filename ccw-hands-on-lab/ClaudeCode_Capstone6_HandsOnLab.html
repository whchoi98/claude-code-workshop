뉴스룸 렌즈, 4개 매체 관점 비교

RSS 수집 → 토픽 클러스터 → 매체별 프레이밍 비교, LLM이 아니면 못 만드는 화면

같은 사건도 뉴스룸마다 다르게 부릅니다. BBC, The Guardian, NHK World, 연합뉴스의 헤드라인을 주기 수집해 나란히 놓고, Bedrock이 공통 토픽을 묶어 매체별 프레임을 한국어로 비교합니다. 요약을 넘어 관점을 읽는 도구 - 이것이 LLM 고유의 화면입니다. 키 발급 없음, 마감은 CloudFront 실배포, 120분에 완결합니다.

소요 시간 120분 미션 5개 + DoD 산출물 공개 URL로 열리는 내 미디어 렌즈 Update 2026.08

빈 폴더에서 superpowers 워크플로로 설계하고 Phase 단위로 빌드합니다. 2시간 트랙이라 키 발급이 없고(4개 매체 공개 RSS), 마감은 CloudFront 실배포입니다. 소스는 영문 3개 + 한국어 1개지만, 화면의 토픽과 비교 브리핑은 전부 한국어입니다(원문 제목 병기).

1) 구조: backend/(Python 3.11+ FastAPI, app/collector 수집, app/store, app/api, app/llm, config.py)
   + frontend/index.html(빌드 없는 정적 SPA 한 장). FastAPI가 정적 파일을 함께 서빙해 :8000 완결.

   BBC World, The Guardian World, NHK World(영문), 연합뉴스 국제 - 각 항목은 {id, 이름, 언어, rss_url}.

6) 렌즈(LLM, 이 캡스톤의 심장): Bedrock Converse를 SDK 없이 httpx 직접 REST로.
   POST https://bedrock-runtime.ap-northeast-2.amazonaws.com/model/global.anthropic.claude-sonnet-4-6/converse
   Authorization: Bearer(환경변수 AWS_BEARER_TOKEN_BEDROCK), maxTokens 1500.
   입력은 4개 소스의 최신 헤드라인+요약 묶음. 출력은 반드시 JSON만:
   {"clusters":[{"topic":"한국어 토픽명","summary":"공통 사실 2문장",
     "frames":{"bbc":"이 매체의 프레임 1문장","guardian":"...","nhk":"...","yna":"..."},
     "sources":{"bbc":[기사 인덱스],...}}], "overview":"오늘의 미디어 지형 3문장"}

   모든 생성 텍스트는 한국어, 기사 제목 원문은 화면에서 병기

   "렌즈" 버튼 → 클러스터 뷰: 토픽 카드마다 공통 요약 + 4개 매체 프레임을 나란히,
   미보도는 회색 처리, 근거 기사 링크 칩. 뷰 전환 토글
8) 키와 윤리: Bearer는 환경변수로만. 기사 본문을 저장하지 않는다(헤드라인+요약+링크만),
   화면 모든 카드에 원문 출처 링크 필수
9) 배포와 순서: CDK로 CloudFront → (prefix list SG + X-Origin-Verify) ALB → Fargate 를 구성,
   Secrets 기동 주입. Phase 1(수집 + 스토어 + /api/articles) → Phase 2(4열 그리드)

   curl과 브라우저로 검증. 결정이 필요하면 이 범위 안에서 최소한으로만 물어봐.
자동화 옵션, auto mode 세션에 auto mode on을 선언해 두면 superpowers가 brainstorming → write-plan → execute-plan의 단계 전환과 승인 대기를 자동으로 이어 갑니다. 시간이 빠듯할 때 유용합니다. 되돌리려면 auto mode off입니다.

개념 짚기 (Level 200), 정규화가 비교를 만든다 BBC와 연합뉴스의 RSS는 필드도, 날짜 형식도, 인코딩 습관도 다릅니다. 4개 피드를 {source, title, link, published, summary} 한 가지 모양으로 다듬는 순간에야 "나란히 놓기"가 가능해지고, 렌즈 프롬프트도 단순해집니다. 통합의 8할은 정규화입니다 - 그리고 summary의 HTML 태그 제거와 절단은 프롬프트 토큰 예산을 지키는 실무 규율입니다.

개념 짚기 (Level 200), 관점을 묻는 프롬프트 "요약해줘"는 아무 모델이나 합니다. 이 캡스톤의 프롬프트는 세 가지가 다릅니다: ① 비교 지시 - "각 매체가 무엇을 앞세우고 무엇을 생략하는지"를 명시적으로 묻고, ② 침묵의 처리 - 다루지 않은 매체를 "미보도"로 표기하게 해 부재 자체를 정보로 만들며, ③ JSON 계약 - 출력이 화면 데이터이므로 스키마 밖 산문을 금지합니다. 그리고 근거 인덱스(sources)를 요구하는 순간, 렌즈는 주장이 아니라 링크로 검증 가능한 화면이 됩니다.
렌즈나 배포가 막힐 때 ① JSON 파싱 실패 = 응답 앞뒤의 코드펜스가 남은 것, 방어적 제거를 확인하세요. ② 클러스터가 1개뿐 = 정상일 수 있습니다, 조용한 뉴스 시간대엔 공통 토픽이 적습니다. ③ ALB 직접 접근 403 = 정상(이중 방어), ④ 브리핑만 실패 = 태스크 정의의 secrets 블록에서 Bearer 주입 확인.
