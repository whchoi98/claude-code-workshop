# 브리핑 (PowerPoint)

요청: $ARGUMENTS

요청이 비어 있으면 `work/` 폴더에 있는 현황판과 통계표 자료를 묶어 브리핑을 만든다. 그것도 없으면 강남역을 주제로 만든다.

브리핑은 자료 파일(JSON) 하나로 만든다. 표지와 출처 장은 도구가 붙이므로 본문 장만 쓴다.

## 순서

1. `${CLAUDE_SKILL_DIR}/../../kit/data-guide.md`를 읽는다.
2. `work/` 폴더를 본다. 같은 주제의 현황판이나 통계표 자료가 있으면 그 숫자를 다시 쓴다. 이미 확인한 숫자를 도구로 또 부르지 않는다.
3. 빠진 자료를 채운다. 숫자는 서울 MCP에서, 배경이 되는 사실(정책, 최근 소식, 다른 지역과의 비교)은 필요할 때 웹에서 하나만 찾아 출처와 함께 넣는다. 웹 자료가 없어도 브리핑은 완성된다.
4. 이야기 순서를 정한다. 보통 "지금 상태, 흐름, 비교, 읽어 낸 것과 다음 할 일" 순이다.
5. 자료 파일을 `work/<짧은-영문-이름>.json`에 쓴다. Write 도구로 직접 쓰고 셸이나 python으로 만들어 쓰지 않는다.
6. 만든다.
   ```bash
   python3 "${CLAUDE_SKILL_DIR}/../../kit/kit.py" deck work/<이름>.json
   ```
   명령은 위 모양 그대로 하나씩 실행한다. 경로를 변수에 담거나 `&&`, `;`, `|`로 여러 명령을 묶으면 사용자에게 승인 창이 뜬다. 출력이 길어도 `head`나 `sed`를 붙여 자르지 않는다.
   `[검사 실패]`가 나오면 알려 준 칸만 고쳐 다시 실행한다.
7. 사용자에게 알린다. 결과 보관함에서 내려받는다는 것, 장마다 한 줄 결론, 출처, 발표자 노트를 넣었다는 것을 짧게 적는다.

## 자료 모양

정확한 규칙은 `python3 "${CLAUDE_SKILL_DIR}/../../kit/kit.py" rules deck`, 완성된 예시는 `... kit.py example deck`로 본다.

- `title`, `subtitle`, `presenter`, `date`, `theme`, `slides`(본문 2~8장), `sources`. `presenter`와 `date`는 모르면 항목을 빼고 빈 글로 두지 않는다.
- `theme`은 `ink`(남색), `forest`(초록), `sunset`(주황), `ocean`(청록). 사용자가 고르지 않으면 `ink`.
- 장의 `type`은 네 가지다.

  | type | 쓰임 | 필요한 것 |
  |---|---|---|
  | `numbers` | 큰 숫자 2~4개 | `items`: `label`, `value`(글자, 10자 이하. 예: "5.4만"), `unit`, `note`, `signal` |
  | `chart` | 흐름이나 크기 비교 | `chart`(column, bar, line, pie), `categories`, `series`, `unit` |
  | `table` | 항목별 비교 | `columns`(2~6열. 열마다 `label`과 `type`을 적고 `label`은 12자 이하), `rows`(2~8줄, 칸마다 24자 이하) |
  | `bullets` | 읽어 낸 것, 다음 할 일 | `bullets` 2~5줄 |

- 모든 장에 `title`(36자 이하)과 `takeaway`(60자 이하)를 쓴다. `takeaway`는 그 장의 한 줄 결론이다.
- `notes`에는 발표할 때 읽을 말을 적는다(400자 이하). 숫자의 기준 시각과 주의할 점을 여기에 둔다.

## 좋은 브리핑

- 한 장에는 한 가지만 말한다. 차트 하나에 계열은 셋까지만 넣는다.
- `takeaway`는 "무엇이 어떻다"로 끝나는 문장으로 쓴다. 제목을 되풀이하지 않는다.
- 줄이 8줄을 넘는 표는 통계표(Excel)로 돌리고 브리핑에는 위에서 다섯 줄만 싣는다.
- 마지막 본문 장은 `bullets`로 읽어 낸 것과 다음 할 일을 적는다.
