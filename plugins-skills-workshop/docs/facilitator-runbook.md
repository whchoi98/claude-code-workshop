# Day 1 진행자 운영안

비개발 직군 중심의 2일 과정 가운데 Day 1을 다룬다. Day 2는 일주일 뒤에 연다. 참가자는 데이터 사이언티스트, 데이터 담당자, 비개발 직군이고 개발자가 일부 섞여 있다. LAB은 각자 진행한다.

## 1. 하루 흐름

| 시간 | 세션 | 이 운영안에서 챙길 것 |

## 2. LAB 진행표 (120분)

| 시간 | 미션 | 산출물 | 진행자가 할 일 |
|---|---|---|---|
| 0~5분 | 준비 4~5번 | Claude Code 시작, 연결 확인 | 오전에 준비 1~3번을 못 마친 사람을 먼저 찾아 돕는다 |

| 35~60분 | 2. 통계표 | Excel | Excel에서 "편집 사용"을 눌러야 한다는 것을 시작할 때 말한다 |

2시간에 맞추려고 가이드에서 줄인 것은 세 가지다. "말로 고치기"는 셋 가운데 하나만 필수이고, 웹에서 찾는 단계(미션 2와 3)는 체크포인트 뒤의 "먼저 끝났다면"으로 옮겼고, 미션 4는 현황판 하나만 직접 만든 뒤 내 Skill이 통계표와 브리핑까지 만든다. 내 Skill 저장은 Day 1에 끝낸다.

- **오전에 준비 1~3번을 못 마쳤을 때**: LAB 시작에 10분쯤 더 든다. 쉬는 시간을 5분으로 줄이고 미션 4의 3번(내 업무 한 줄)을 숙제로 돌려 맞춘다. 내 Skill 저장은 줄이지 않는다.
- **150분으로 늘릴 때**: "말로 고치기"를 셋 다 하고, 웹에서 찾는 단계 두 개를 모두가 한다.
- **3시간으로 늘릴 때**: 150분 구성에 더해 도전 과제 시간을 주고, 마지막에 서로의 결과 보관함을 구경하는 시간 10분을 둔다.

## 3. 사전 준비

### 일주일 전

- [ ] 서울 MCP 워크숍 Gateway가 떠 있는지 확인한다. 배포, 코드 발급, 스냅샷 수집은 `seoul-opendata-mcp` 저장소의 `docs/workshop.md`를 따른다. 2026-11-24에 Gateway에 연결해 tool 23개가 보이는 것을 확인했다. Gateway 주소는 랩 가이드 준비 3번과 "막히면" 첫 항목의 명령에 들어 있다. 스택을 새로 만들어 주소가 바뀌면 `lab/`의 원본에서 두 곳을 고치고 통합 스크립트를 다시 실행한다.
- [ ] 서울 열린데이터광장 API 키 수와 분당 한도를 참가자 수에 맞춘다(아래 4번).
- [ ] 실습 서버에는 미리 설치할 것이 없다. 참가자가 랩 가이드 준비 1번에서 워크숍 저장소를 받고 `scripts/setup-lab.sh`를 직접 실행한다. 이 스크립트가 플러그인 마켓플레이스를 `~/workshop-kit`에, 작업 폴더를 `~/seoul-lab`에 두고 `openpyxl`과 `python-pptx`를 설치한다. 서버에서 `git`, `python3`를 쓸 수 있는지와 github.com, pypi.org로 나가는 통신이 되는지만 미리 확인한다. 통신이 막힌 환경이면 진행자가 서버마다 같은 스크립트를 미리 실행해 둔다.
- [ ] 랩 가이드를 게시한다. 가이드는 기존 핸즈온 랩 사이트의 한 파트(`ccw-hands-on-lab/ClaudeCode_Day1_SeoulData_HandsOnLab.html`, 사이드바의 캡스톤 · 프로젝트 선택 M7)로 들어가 있다. 워크숍 저장소와 github.io 저장소를 커밋하고 github.io를 push해야 공개된다.
- [ ] 참가자 노트북에 Excel과 PowerPoint가 있는지 확인한다. 없으면 웹 버전으로 열 수 있는지 확인한다.

### 하루 전 리허설

- [ ] 참가자 서버 한 대에서 랩 가이드를 처음부터 끝까지 따라 한다.
- [ ] code-server 주소 끝에 `/proxy/8000/`을 붙여 결과 보관함이 열리는지 본다.
- [ ] 내려받은 통계표와 브리핑을 실제 Excel과 PowerPoint에서 연다. 한글 글꼴, 수식 계산, 차트 편집을 확인한다.
- [ ] 참가자가 쓸 모델로 Skill 세 개를 한 번씩 돌려 걸리는 시간을 잰다.
- [ ] 서울 MCP를 끊은 상태에서 "미리 받아 둔 자료로 만들어 줘"가 통하는지 본다.
- [ ] 워크숍 코드를 발급한다(`seoul-opendata-mcp`에서 `npm run workshop:code -- new --days 2`). 새 코드를 발급하면 이전 코드는 바로 거부된다. 발급한 뒤에는 LAB이 끝날 때까지 다시 발급하지 않는다.
- [ ] 참가자 서버 한 대에서 준비 3번을 새 코드로 해 보고 `claude mcp list`의 `seoul` 줄이 Connected인지 본다.

## 4. 호출 한도

2026-11-24에 워크숍 Gateway에 연결해 잰 값이다(Sonnet, 헤드리스).

| 미션 1 도전 과제(대표 핫스팟 7곳 현황판) | 9. 장소 7번에 이름 찾기 2번 |
| 현황판에 도로와 미세먼지 더하기 | 4 |
| 현황판에 주차장이나 따릉이 열 더하기 | 3~5 |

| 고치기 세 개와 웹 단계까지 모두(미션 3 끝까지 문장 18개) | 15 |

가이드의 필수 경로만 따라 하면 한 명이 12번쯤, 고치기와 웹 단계까지 모두 하면 15번쯤 부른다. 다른 주제를 더 만들거나 다시 시키는 것까지 넣어 한 명에 20~40번으로 잡으면 30명에 600~1,200번이다. Gateway 설계의 기본값은 키 하나당 하루 1,000번, 전체 분당 120번이다. 승하차 통계, 문화행사, 주차장 안내처럼 Gateway가 미리 받아 둔 스냅샷으로 답하는 요청은 서울 API 한도를 쓰지 않는다(`seoul-opendata-mcp`의 `docs/workshop.md`).

- 키는 2~3개를 준비한다.
- 미션 1을 모두가 같은 분에 시작하면 분당 한도에 닿을 수 있다. 분당 한도를 그날만 올리거나, "준비가 끝난 분부터 시작하세요"라고 말해 시작이 자연스럽게 흩어지게 한다.
- 한도 안내가 나온 참가자에게는 1분 뒤 다시 시키라고 알려 준다.
- 미션 1 도전 과제는 장소를 대표 핫스팟 7곳(강남역, 홍대 관광특구, 명동 관광특구, 잠실 관광특구, 광화문, 여의도, 성수)으로 정해 두었다. 서울 전체에서 가장 붐비는 곳을 찾게 하면 핫스팟 121곳을 차례로 불러 한 명이 분당 한도를 채울 수 있다. 7곳이면 한 명에 9번이다.
- Gateway는 실시간 도시데이터를 5분 동안 저장해 두고, 그보다 오래된 저장본이 있으면 그 값을 먼저 준 뒤 뒤에서 새로 받는다. 한동안 아무도 부르지 않은 장소는 첫 응답의 기준 시각이 몇 시간 전일 수 있고, 응답에 "캐시된 데이터"라는 안내가 붙는다. 시험에서는 104~223분 전 값이 왔고, 2분 뒤 다시 불렀을 때 7곳 가운데 6곳이, 한 번 더 불렀을 때 나머지 한 곳이 새 값으로 왔다. LAB 시작 직전에 진행자가 7곳 현황판을 한 번 만들어 두면 참가자가 오래된 값을 받는 일이 줄어든다.

## 5. 서울 MCP가 멈췄을 때

1. 참가자에게 랩 가이드 "막히면"의 두 번째 항목을 안내한다. `data/seoul-sample/`의 자료로 같은 미션을 진행한다.
2. 웹 검색은 서울 MCP와 무관하게 동작하므로 미션 2와 3의 "먼저 끝났다면, 웹에서" 단계는 그대로 할 수 있다.
3. 미션 4는 서울 MCP를 쓰지 않는다. 길게 멈추면 미션 4를 앞당긴다.

LAB 중에 워크숍 코드를 새로 발급하면 이전 코드로 등록한 모든 참가자의 연결이 끊긴다. 2026-11-24 시험 도중 코드가 바뀌었을 때 Claude는 "서울 데이터 서버가 워크숍 코드를 거부한다"고 알렸고, 통계표는 미리 받아 둔 자료로 만들면서 기준 시각 칸과 출처 시트에 그 사실을 적었다. 값을 지어내지는 않았다. 코드가 새어 나가 어쩔 수 없이 바꿨다면 새 코드를 화면에 띄우고, 참가자에게 랩 가이드 "막히면"의 첫 항목(지우고 다시 등록)을 하게 한 뒤 Claude Code를 다시 시작하게 한다.

## 6. 미션별 진행 요령

### 미션 1, 현황판

- 장소를 스스로 고르게 한다. 예시 그대로 치는 참가자에게는 "회사 근처는 어디예요?"라고 묻는다.
- 장소 이름이 121곳에 없으면 Claude가 가까운 후보를 제안한다. 당황하지 않게 미리 말해 둔다.
- "일부러 틀려 보기"는 건너뛰지 않게 한다. 오전 거버넌스 세션과 이어지는 대목이다.

### 미션 2, 통계표

- 가장 흔한 막힘은 Excel의 보호된 보기다. 합계가 0으로 보이면 "편집 사용"을 누르게 한다.
- 부동산 실거래는 관심이 높지만 건물 이름이 그대로 나온다. 화면을 비출 때는 지하철이나 대기질 표를 고른다.
- 웹 보강 단계에서 Claude가 "찾지 못했다"고 답하는 것도 정상이다. 지어내지 않았다는 점을 짚어 준다.

### 미션 3, 브리핑

- 주제를 비워 두면 앞의 두 결과를 묶는다. 미션 1과 2의 주제가 다르면 주제를 직접 적게 한다.
- "검산하기"는 데이터 직군에게 특히 강조한다. 숫자가 어느 자료에서 왔는지 되짚는 습관이 이 과정의 핵심이다.

### 미션 4, 내 업무로

- 실제 업무 자료는 올리지 않게 한다. 연습용 `team-kpi.csv`만 쓴다.
- 내 Skill을 저장할 때 승인 창이 뜬다. Claude가 자기 설정 폴더(`.claude/`)에 쓰려 할 때는 항상 묻는다는 점을 짚어 준다.
- 내 Skill을 만든 뒤에는 Claude Code를 다시 시작해야 목록에 보인다.
- 팀 지표로는 현황판 하나만 직접 만들고 바로 내 Skill로 저장한다. 통계표와 브리핑은 그 Skill을 실행할 때 함께 만들어진다. 한 줄로 세 결과가 나오는 순간이 이 과정의 마무리다.

개발자에게는 도전 과제와 함께 옆 사람을 돕는 역할을 권한다.

## 8. 일주일 간격을 쓰는 법

Day 1 숙제는 세 가지다.

1. 되풀이하는 내 업무 한 가지를 한 줄로 적어 온다.
2. 그 업무에 쓰는 자료의 모양을 메모해 온다. 실제 숫자와 개인정보는 가져오지 않는다.
3. 오늘 만든 결과 하나를 동료에게 보여 주고 반응을 들어 온다.

사흘 뒤쯤 참가자에게 알림을 한 번 보낸다. 랩 가이드 주소와 숙제 세 줄이면 된다. Day 2는 숙제를 두세 명이 나누는 10분으로 시작하는 안을 권한다.

- 참가자 여러 명이 같은 분에 부를 때의 분당 한도. 시험은 동시에 다섯 갈래까지였다
- 실제 실습 서버에서의 준비 1번. 컨테이너 시험에서 Amazon Linux 2023은 일반 계정으로도 통과했다. Ubuntu 24.04는 pip이 없는 일반 계정에서 `sudo`를 쓸 수 없으면 `[중단]` 안내를 내고 멈췄다. 암호 없는 `sudo`로 `python3-pip`을 설치하는 경로는 시험하지 못했다. 실습 서버가 Ubuntu라면 리허설에서 이 단계를 먼저 본다
- code-server의 `/proxy/8000/` 경로로 결과 보관함 열기
- 대화형 화면에서 승인 창이 실제로 뜨는 모양과 빈도. 헤드리스 시험은 작업 폴더 신뢰 확인을 거치지 않아 `.claude/settings.json`의 허용 목록 대신 같은 규칙을 실행 옵션으로 줬다. 그 조건에서 필수 경로의 승인 요청은 내 Skill 저장 1번이었다. 고치기를 더 시키면 Claude가 명령을 한 줄로 묶어 승인 창이 더 뜰 수 있다. 앞선 시험에서 규칙 조회에 `sed`를 파이프로 붙인 1건이 있었고, 그 뒤 Skill 문서에 묶지 말라는 안내를 넣었다
- 미션 4의 내 Skill 저장을 대화형 화면에서 하기. 승인 요청에 허용으로 답하는 도구를 붙인 헤드리스 시험에서는 저장과 실행이 통과했다. 실제 승인 창에서 Yes를 고르는 과정과, 저장한 뒤 Claude Code를 다시 시작해야 목록에 보이는지는 리허설에서 본다
- 비개발 참가자가 실제로 쓰는 시간. 잰 것은 Claude 실행 시간뿐이다(필수 경로 5.6분). 120분 배분은 상자 하나에 읽기와 붙여 넣기와 결과 보기까지 2~3분으로 잡은 추정이다
- 참가자가 쓸 모델에서의 속도와 비용. Sonnet 시험에서는 Skill 한 번에 0.10~0.20달러, 120분 필수 경로 전체에 1.03달러, 고치기와 웹 단계까지 모두 하면 미션 3 끝까지 1.24달러가 들었다
