# Plugins & Skills 세션 구성안 (50분)

Day 1 점심 직후 세션이다. 이 세션이 끝나면 바로 LAB으로 넘어간다. 청중은 데이터 사이언티스트, 데이터 담당자, 비개발 직군이 대부분이고 개발자가 일부 섞여 있다.

## 이 세션이 남겨야 할 것

1. Skill은 "설명서, 재료, 도구"를 한 폴더에 담은 것이다.
2. Plugin은 Skill과 연결 설정을 한 번에 설치하고 팀에 나눠 주는 단위다.
3. AI에게는 자료만 쓰게 하고, 결과물은 정해진 도구가 만들게 하면 품질이 일정해진다.

용어 설명보다 시연을 앞에 둔다. 슬라이드는 12장 안쪽으로 잡는다.

## 시간 배분

| 시간 | 내용 | 방식 |
|---|---|---|
| 0~7분 | 문제 보여 주기: 같은 보고를 매번 길게 시킨다 | 시연 1 |
| 7~17분 | Skill 해부: 설명서, 재료, 도구 | 슬라이드와 폴더 열어 보기 |
| 17~25분 | 규칙과 검사: 일부러 틀려 보기 | 시연 2 |
| 25~35분 | Plugin: 묶어서 설치하고 나눠 주기 | 슬라이드와 시연 3 |
| 35~43분 | 거버넌스 연결: 누가 무엇을 허용하나 | 슬라이드 |
| 43~50분 | LAB 안내 | 랩 가이드 화면 |

## 시연 1, 긴 요청과 한 줄 요청 (0~7분)

준비: 작업 폴더에서 Claude Code를 띄워 두고, 결과 보관함 탭을 열어 둔다.

1. 긴 요청을 화면에 띄운다. 직접 타이핑하지 말고 미리 써 둔 것을 붙여 넣는다.

   ```text
   서울 MCP로 강남역, 여의도, 성수카페거리의 실시간 인구와 혼잡도를 가져와 줘.
   HTML 한 파일로 현황판을 만들어 줘. 큰 숫자 카드를 위에 두고 아래에 비교표를 넣어 줘.
   혼잡도는 신호등 색으로 보여 주고, 표는 눌러서 정렬되게 해 줘.
   출처와 기준 시각을 맨 아래에 적고, 숫자는 지어내지 마. 글꼴은 ...
   ```

   말할 것: "지난주에도 이렇게 시켰고 다음 주에도 이렇게 시킬 겁니다. 시킬 때마다 화면 모양이 조금씩 다르게 나옵니다."

2. 한 줄 요청을 실행한다.

   ```text
   /seoul-kit:board 강남역, 여의도, 성수
   ```

   20초쯤 뒤 결과 보관함에서 현황판을 열고, 표 머리글 정렬과 발표 모드(P)를 보여 준다.

   말할 것: "긴 요청이 사라진 게 아닙니다. 어딘가에 저장돼 있습니다. 그 저장된 것이 Skill입니다."

## Skill 해부 (7~17분)

code-server 탐색기에서 `~/workshop-kit/plugins/seoul-kit` 폴더를 연다.

| 보여 줄 파일 | 비유 | 말할 것 |
|---|---|---|
| `skills/board/SKILL.md` | 설명서 | 맨 위 `description`이 "언제 이 Skill을 쓰는가"다. Claude는 이 설명을 보고 스스로 꺼내 쓴다 |
| `kit/board_template.html` | 재료 | 화면 틀이다. 디자인과 움직임이 여기 고정돼 있다 |
| `kit/kit.py` | 도구 | 자료를 받아 검사하고 파일을 만든다. 사람이 만든 정해진 절차다 |
| `kit/data-guide.md` | 사내 지침 | 숫자를 어디서 가져오고 어떻게 다루는지를 세 Skill이 함께 따른다 |

슬라이드 한 장으로 정리한다.

- 설명서(SKILL.md): 언제, 어떤 순서로
- 재료(틀, 예시): 무엇을 바탕으로
- 도구(스크립트): 틀리지 않게

질문을 하나 던진다. "여러분 팀에서 매주 되풀이하는 보고 가운데, 순서가 정해져 있는 것은 무엇입니까?" 두세 명에게 답을 듣는다. 이 답이 LAB 미션 4와 숙제로 이어진다.

## 시연 2, 일부러 틀려 보기 (17~25분)

1. `work/` 폴더의 자료 파일을 열어 보여 준다. "Claude가 쓴 것은 이 자료 파일 하나입니다. 화면은 쓰지 않았습니다."
2. 자료 파일에서 `"signal": "green"`을 `"signal": "blue"`로 직접 고치고 저장한다.
3. Claude에게 "다시 만들어 줘"라고 시킨다. 검사 실패 문구가 나온다.

   ```text
   [검사 실패] 현황판 자료 work/three-places.json 에서 고칠 곳 1군데
     - cards[0].signal: green, yellow, red, none 가운데 하나여야 합니다(지금 「blue」)
   ```

4. 말할 것: "사람이 틀려도, AI가 틀려도 같은 문에서 걸립니다. 규칙이 설명서에만 적혀 있으면 지켜지길 바랄 뿐이지만, 도구 안에 있으면 지켜집니다."
5. 되돌리고 다시 만든다.

통계표의 수식 허용 목록도 한 줄로 언급한다. "통계표에는 SUM, RANK 같은 정해진 함수만 들어갑니다. 바깥 파일이나 웹을 부르는 수식은 도구가 막습니다."

## Plugin (25~35분)

슬라이드 두 장.

1. Plugin 안에 들어가는 것: Skill, MCP 연결, 훅, 명령. 오늘 쓰는 seoul-kit에는 Skill 세 개와 공용 도구가 들어 있다.
2. Marketplace: 플러그인 목록을 담은 폴더나 저장소. 팀 저장소 하나가 곧 팀의 marketplace가 된다.

시연 3. 터미널에서 설치 두 줄을 실행한다. 참가자는 LAB 준비 단계에서 같은 명령을 직접 실행한다.

```bash
claude plugin marketplace add ~/workshop-kit
claude plugin install seoul-kit@workshop-kit
```

말할 것: "팀장이 양식을 바꾸면 플러그인 버전을 올립니다. 팀원은 업데이트만 받으면 다음 보고부터 새 양식으로 나옵니다."

## 거버넌스 연결 (35~43분)

오전 "설정과 거버넌스" 세션과 잇는다. 슬라이드 두 장.

| 질문 | 오늘 LAB에서의 답 |
|---|---|
| 누가 어떤 데이터에 닿을 수 있나 | 서울 MCP는 워크숍 코드가 있어야 열린다. 코드는 만료된다 |
| 어떤 행동이 승인 없이 되나 | 작업 폴더의 설정 파일이 서울 MCP, 웹 검색, 결과물 만들기만 미리 허용한다 |
| 숫자는 어디서 왔나 | 모든 결과물에 출처와 기준 시각이 붙는다. 웹 숫자는 직접 연 페이지만 쓴다 |
| 어떤 플러그인을 쓸 수 있나 | 조직이 허용한 marketplace의 플러그인만 설치하게 정할 수 있다 |

작업 폴더의 `.claude/settings.json`을 화면에 띄워 허용 목록과 금지 목록을 보여 준다. "오전에 본 그 파일입니다. 이 파일 덕분에 오후 LAB에서 승인 창이 거의 뜨지 않습니다."

## LAB 안내 (43~50분)

랩 가이드(`lab/ClaudeCode_Day1_SeoulData_HandsOnLab.html`)를 화면에 띄우고, 맨 앞의 실습 구조 그림으로 오늘 본 Skill, Plugin, 검사 규칙, 권한 설정이 LAB에서 어디에 쓰이는지 짚은 뒤 다음을 알린다.

- 준비 3번에서 서울 데이터를 연결한다. 명령 끝의 `seoul-XXXX-XXXX`를 화면에 띄운 워크숍 코드로 바꿔 넣는다. 코드는 가이드에 없으므로 준비가 끝날 때까지 화면에 띄워 둔다.
- 각자 자기 속도로 진행한다. 미션은 현황판, 통계표, 브리핑 순서다.
- 상자 오른쪽의 복사를 눌러 붙여 넣는다. 장소와 역 이름은 자기 것으로 바꾼다.
- 미션마다 "먼저 끝났다면" 과제가 직군별로 있다.
- 막히면 가이드 맨 아래를 먼저 보고, 그래도 안 되면 손을 든다.
- 결과 보관함 탭을 열어 두면 새 결과가 스스로 나타난다.

마지막 한 마디: "오늘 고르는 장소는 여러분이 정합니다. 숫자는 지금 이 순간의 값이라 옆 사람과 결과가 다릅니다."

## 준비물 점검

- [ ] 진행자 서버에서 랩 가이드 준비 1번(자료 받기)을 마쳐 `~/workshop-kit`과 `~/seoul-lab`이 있다
- [ ] 진행자 서버에서 준비 3번(서울 데이터 연결)을 마쳐 `claude mcp list`의 `seoul` 줄이 Connected로 보인다
- [ ] 워크숍 코드를 크게 적은 화면을 준비했다. 코드는 저장소, 공개 페이지, 채팅방에 올리지 않는다
- [ ] 진행자 화면에서 시연 1~3을 처음부터 끝까지 한 번 돌려 봤다
- [ ] 서울 MCP가 응답하지 않을 때 보여 줄 완성본(`out/` 폴더 사본)을 준비했다
- [ ] 긴 요청 문구를 메모장에 붙여 넣기 좋게 준비했다
- [ ] 글자 크기를 프로젝터에서 뒤쪽 자리까지 읽히게 키웠다
